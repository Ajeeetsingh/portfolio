The Problem

Documents built for people, not parsers.

U.S. real estate records arrive scanned and inconsistent: rotated pages, stamps over text, typed and handwritten marks side by side, tables that only look like tables. A legal land description can run for paragraphs of boundary calls.

Generic OCR reads the characters and loses the meaning. A language model asked to read the whole page fills the gaps it can't see. Either way the extracted value has to be right, because something downstream depends on it, and a reviewer has to be able to confirm it quickly.

The Approach

Narrow the page before asking a model to read it.

Specialized CV preprocessing paired with domain-fine-tuned LLMs & vision-language models.

A Document Ingestion & Computer Vision Preprocessing Specifications
3 Pipeline Stages · Ingress Normalization
01 Ingestion & Deskew
OpenCV Normalizer

FastAPI on AWS receives scans; OpenCV deskews orientation, denoises speckle, and scales DPI.

Engineering Rationale Deskewing and normalizing contrast once at ingress eliminates orientation hallucinations inside downstream model calls.
Input / Output Boundary Multi-page TIFF, PDF, JPEG scans → Normalized 300 DPI oriented image arrays.
Safeguard / Metric 100+ documents/day processed with zero orientation failure retries.
02 Region Segmentation
CV Detection

Computer vision locates legal text blocks, boundary tables, parcel polygons, and notary stamps.

Engineering Rationale Passing whole complex pages into LLMs leads to hallucinated fields. Isolating text blocks produces high-precision crops.
Input / Output Boundary Full page image → Bounding box coordinate arrays with region classification tags.
Safeguard / Metric Crops page into targeted sub-sections; eliminates 90% background noise.
03 Modal Dispatcher
Routing Gate

Categorizes crops: legal deeds go to Fine-Tuned LLMs; maps go to Classical CV + VLM.

Engineering Rationale Legal deeds require linguistic reasoning; maps require spatial visual reasoning. Routing each region optimizes accuracy and cost.
Input / Output Boundary Region crops → Dispatched to Fine-Tuned LLMs OR Multimodal VLM reader.
Safeguard / Metric Zero wasted LLM calls on visual diagrammatic areas.
B Specialized Neural Reading & Guardrails Specifications
4 Pipeline Stages · LLM + VLM Inference
04 Text Field Extraction
Fine-Tuned LLM

Fine-tuned models extract metes & bounds, PINs, and grantors with ~15–20% higher accuracy than baseline.

Engineering Rationale Generalist LLMs struggle with archaic real estate legalese. Models fine-tuned on county records extract clean schema fields.
Input / Output Boundary Legal text crops → Structured JSON (Grantor, Grantee, PIN, Legal Land Description).
Safeguard / Metric 15–20% higher extraction accuracy than general-purpose LLM baselines.
05 Parcel Map Geometry
Classical CV + VLM

Classical CV isolates parcel boundaries; vision-language models read lot numbers and compass rose orientation.

Engineering Rationale Classical CV accurately detects polygon vertices and frontages; a VLM reads lot numbers and compass rose orientations.
Input / Output Boundary Assessor parcel map crops → Vector geometry coordinates + orientation angle.
Safeguard / Metric Automates hand-marked map indexing that previously required manual surveying.
06 Schema Validation
Pydantic Guard

Rigid type validation & domain rule checks reject malformed extractions, cutting errors by ~90%.

Engineering Rationale Rigid validation ensures bad extractions fail at the pipeline boundary rather than corrupting downstream title registries.
Input / Output Boundary Structured JSON candidate → Strict Pydantic validated models.
Safeguard / Metric ~90% fewer extraction errors escaping into downstream systems.
07 Human-in-the-Loop
Review Loop

Low-confidence predictions surface beside the exact document crop for 2-second reviewer verification.

Engineering Rationale Predictions below strict confidence thresholds surface side-by-side with original crop, enabling instant human verification.
Input / Output Boundary Flagged fields + document crop → 1-click human verification console.
Safeguard / Metric Cuts manual processing effort by ~80% while maintaining 100% legal auditability.

Specialized Pipelines

Text records and maps need different readers.

Property records

Field extraction with fine-tuned LLMs

Extracts, validates and structures fields such as legal land descriptions from mortgage, title and ownership documents. LLMs fine-tuned on real estate data outperform general-purpose models on these fields, and RAG with semantic chunking supplies context across large document sets.

Assessor parcel maps

Computer vision + a vision-language model

Classical computer vision isolates parcel geometry and markings; a vision-language model reads them back, including the map's compass orientation. Each tool does the part it's good at.

Engineering Decisions

What makes it hold up.

Vision first, language second

Isolating the region first turns an open-ended reading task into a narrow one: more accurate and cheaper per page.

Fine-tune for the domain

Real estate language is specialised. Fine-tuned models extract ~15–20% more accurately than a general-purpose LLM baseline.

Schema at the boundary

Typed, validated outputs mean a bad extraction fails at the pipeline edge, not three systems later.

Context over guesswork

Model and pipeline optimisation cut unsupported or hallucinated outputs, with retrieval supplying the surrounding record.
