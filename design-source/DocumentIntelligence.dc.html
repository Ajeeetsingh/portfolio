01 — The problem

Documents built for people, not parsers.

U.S. real estate records arrive scanned and inconsistent: rotated pages, stamps over text, typed and handwritten marks side by side, tables that only look like tables. A legal land description can run for paragraphs of boundary calls.

Generic OCR reads the characters and loses the meaning. A language model asked to read the whole page fills the gaps it can't see. Either way the extracted value has to be right, because something downstream depends on it — and a reviewer has to be able to confirm it quickly.

03 — Two pipelines

Text records and maps need different readers.

Property records

Field extraction with fine-tuned LLMs

Extracts, validates and structures fields such as legal land descriptions from mortgage, title and ownership documents. LLMs fine-tuned on real estate data outperform general-purpose models on these fields, and RAG with semantic chunking supplies context across large document sets.

Assessor parcel maps

Computer vision + a vision-language model

Classical computer vision isolates parcel geometry and markings; a vision-language model reads them back, including the map's compass orientation. Each tool does the part it's good at.
